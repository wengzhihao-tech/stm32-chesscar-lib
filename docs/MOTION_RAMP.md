# 运动斜坡：软启动、换向与低速下限

> 2026-10-26 新增模块 `common/motion_ramp.*` 的设计依据、踩坑记录与标定步骤。

## 1. 为什么需要独立的一层

上层（`match_fsm` / `navigator`）算出来的目标速度是**阶跃**的：
状态一切换，目标就从 0 跳到 30cm/s，或者从 +20 直接翻成 -20。
速度闭环会忠实执行这个阶跃，于是出现三类问题。

### 坑 A：目标阶跃把两路电机同时顶到满占空比

`car_physical_config.h` 记录堵转电流 **2.0A**、额定 **0.5A**。
双路电机同时阶跃，电池内限上的压降很容易把 MCU 拉到欠压复位，
现场表现是「一给速度就重启」，很容易误判成程序跑飞或看门狗没喂。

公开实现普遍用软启动处理，例如 baihao774/stm32-tb6612-driver 的
「每 20ms 占空比 +5%」（见 [`REFERENCES.md`](REFERENCES.md)）。

**但注意那是开环占空比斜坡。** 本库做的是**目标速度**斜坡，
挂在速度闭环**之前**：

```
match_fsm / navigator  →  MotionRamp  →  SpeedControl  →  Motor(TB6612)
                                            ↑
                              急停绕过斜坡，直达 SpeedControl_Stop()
```

把变化率限制加在速度环**之后**（限制 PWM 变化率）是错的——
那等于给闭环串了一个一阶滞后环节，会直接改变已经调好的 PID 增益含义，
表现是「调好的参数上车就振荡」。

### 坑 B：「换向前清 PWM」只解决一拍内的电平时序

`PITFALLS.md` 第 5 条讲的是 `Motor_ApplySide()` 保证同一拍里先把 CCR 清零
再翻方向脚，避免 H 桥两臂同时导通。那是**电气**层面的保护。

但如果上层把目标从 `+30cm/s` 直接改成 `-30cm/s`，车轮还在正转、
H 桥就被要求反转，**机械**冲击与电流尖峰照旧：
齿轮箱要在几十毫秒内吸收整车动能并反向。

正确做法在上层：先减速过零 → 零速保持若干拍 → 再反向加速。
`MotionRamp_Update()` 用 `reversing` 状态机实现这个三段式，
自测断言「换向不会一拍内跮过零点」守着这个行为。

换向过程中角速度一律压向 0：此时车正在停，保留转向分量只会让
一侧轮停一侧轮转，车身被拽偏，停下来时航向已经错了。

### 坑 C：目标速度低于约 3 个量化步长时，速度环只能抖

本车速度量化步长 ≈ **1.42 cm/s**
（13PPR × 4 倍频 × 20.409 减速比、48mm 轮、10ms 一拍，
即 `Encoder_SpeedQuantumCmps()` 的返回值）。

| 目标速度 | 单拍计数 | 量化误差 |
|---|---|---|
| 2 cm/s | 1.4 | 极大，基本不可用 |
| 5 cm/s | 3.5 | ±14% |
| 10 cm/s | 7.0 | ±7% |
| 20 cm/s | 14.1 | ±3.6% |
| 30 cm/s | 21.1 | ±2.4% |

这是 **M 法测速的原理性限制**，不是调 PID 能解决的：M 法分辨率与转速无关，
转速越低误差率越高（ST 官方给了高/中/低速三档实测曲线，
见 [`REFERENCES.md`](REFERENCES.md) 的 M 法/T 法对比条目）。

`PITFALLS.md` 第 13 条已指出「速度环慎用 D 项」是同一个根因的另一面：
D 项会把这个量化噪声直接放大成输出抖动。

工程上三条路：

1. 延长控制周期 —— 20ms 一拍量化步长降到 0.71cm/s，但外环响应变慢；
2. 换高线数编码器 —— GMR 款 500PPR 可彻底解决，要改硬件；
3. **把低于下限的目标直接判为停车** —— 不让闭环在不可分辨区里挣扎。

本库取第三条，默认 `minMoveCmps = 4.3 cm/s ≈ 3 × 量化步长`，
自测断言 `minMoveCmps > 2 × Encoder_SpeedQuantumCmps()`。

**下限只作用于线速度，不作用于角速度**：原地转弯时线速度为 0 而角速度不为 0，
如果连角速度也套下限，车就没法做小角度对准微调了——而对准精度直接决定
推棋子能不能进门。

> `minMoveCmps` 这个数**换电机、换轮径或改控制周期后必须重算，不要照搬。**

## 2. 标定步骤（接在 `TUNING_GUIDE.md` 第 4 步之后）

**必须等速度内环调好再做这一步，顺序不能反。**
斜坡限制的是「目标」，内环本身跟不上目标时，加斜坡只会掩盖问题。

| 参数 | 怎么定 | 默认 |
|---|---|---|
| `accelCmps2` | 从 60 起。起步瞬间若听到电机「咯」一声、或 OLED 上电压明显掉，就减小。 | 60 cm/s² |
| `decelCmps2` | 可比加速大。落地测急停滑行距离，应小于半个棋子间距。 | 120 cm/s² |
| `angularRateCmps2` | 原地转弯轮胎打滑就减小。地面摩擦差异影响很大。 | 90 cm/s² |
| `minMoveCmps` | **现场用 `Encoder_SpeedQuantumCmps()` 算，取 3 倍。** | 4.3 cm/s |
| `reverseHoldCycles` | 换向时有明显齿轮撞击声就加大。1~3 拍。 | 2 拍 |

### 第 1 步：先打印量化步长

上电后打印一次 `Encoder_SpeedQuantumCmps(&encoderConfig)`。
当前配置应得到约 **1.42 cm/s**。

若与此差一倍以上，**回 [`TUNING_GUIDE.md`](TUNING_GUIDE.md) 第 1 步**——
说明 PPR 或减速比填错了，继续往下调是浪费时间。
确认无误后把 `minMoveCmps` 设成该值的 3 倍。

### 第 2 步：验加速时间

`accelCmps2 = 60` 时，0→30cm/s 理论需 500ms（自测已断言恰好 50 拍）。
用 `MotionRamp_IsSettled()` 翻转的时刻打时间戳对照。

实测明显长于 500ms 说明**内环**没跟上目标 →
回第 4 步加 Kp 或前馈，**不要**靠加大 `accelCmps2` 来「提速」，
那只是让目标跑得更快、偏差更大。

### 第 3 步：测急停滑行距离

30cm/s 稳速后调 `MotionRamp_SetTarget(0, 0)`，
读 `SpeedControl_GetCarDistanceCm()` 的增量。

**比赛里有两种停法，别混：**

| 场景 | 调用 | 行为 |
|---|---|---|
| 正常减速、到点停车 | `MotionRamp_SetTarget(0, 0)` | 走 `decelCmps2` 斜坡 |
| 越界、撞到对手、通信超时、故障锁定 | `MotionRamp_EmergencyStop()` + `SpeedControl_Stop()` | 立刻零输出，不走斜坡 |

`navigator` 的「对手过近强制规避」是规则红线，必须走急停那条。

### 第 4 步：测换向冲击

从 +20cm/s 直接命令 -20cm/s，听齿轮箱声音。
有撞击声就加大 `reverseHoldCycles`。

### 记入调参记录表

斜坡参数与**电池电压、地面材质**强相关。
换场地后第一件事就是重测急停距离——`TUNING_GUIDE.md` 末尾的记录表加两列：
`加/减速度` 和 `急停滑行距离`。

## 3. 本次已验证 / 未验证

PC 自测（`cd test && make run-ramp`，22 项断言全部通过）覆盖：

- 单拍步长 = `accel × T`，且斜坡末端精确落在目标上不过冲；
- 0→30cm/s 恰好 50 拍（500ms）；
- 减速走 `decel` 而非 `accel` 斜率；
- 换向全程不出现一拍内跮零，零速保持拍数符合配置；
- 低于下限的线速度目标被归零，而角速度不受影响；
- 急停立刻清零并清除换向状态；
- 非法配置（周期 0、负加速度）被拒绍，全部接口吃 NULL 不崩。

**未验证（必须上车）**：
`accelCmps2` / `decelCmps2` / `angularRateCmps2` / `reverseHoldCycles`
这四个物理值的具体取值，以及 `minMoveCmps` 在实际底盘上的量化步长核对。
数值逻辑正确不等于参数合适。
