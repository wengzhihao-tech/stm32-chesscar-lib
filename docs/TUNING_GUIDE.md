# 标定与调参指南

**顺序很重要。** 跳过前面的步骤直接调 PID，是智能车调试最常见的时间浪费来源：
物理参数错了，PID 永远调不好，因为反馈值本身就是错的。

---

## 第 0 步：安全前提

- 整个标定过程把车**架空**（轮子离地），直到第 4 步才落地。
- 电池电压降到标称值以下时，死区和前馈都会漂移。**全程用同一电量区间标定**。
- 霍尔编码器输出必须是 3.3V 电平并与 STM32 共地。上拉到 5V 的编码器
  不要直接接 GPIO。

---

## 第 1 步：核对机械参数（改 `common/car_physical_config.h`）

| 参数 | 怎么测 |
|---|---|
| `CAR_WHEEL_DIAMETER_CM` | 游标卡尺量**装车后**的轮胎外径。轮胎受压会变形，空载外径偏大。 |
| `CAR_WHEEL_TRACK_CM` | 左右轮胎接地中心距。 |
| `CAR_GEAR_RATIO` | 查电机规格书。MG310 常见为 20.409、30、45 等多个版本，**务必确认手上这款**。 |
| `CAR_MOTOR_ENCODER_PPR` | 霍尔款常见 11/13，GMR 款常见 500。接错会让速度差几十倍。 |

**验证方法（强烈建议做）**：把车推着走直线 1 米，读 `SpeedControl_GetCarDistanceCm()`。
误差超过 3% 就回头查轮径和减速比，不要用软件系数硬凑。

> 倍频系数固定为 4，因为 STM32 编码器模式选 `TI1 and TI2` 时硬件已经四倍频，
> 软件**不要**再乘 4。选成 `TI1 only` 只有 2 倍频，是常见误配。

---

## 第 2 步：确认方向（架空）

这一步只确认符号，不看数值。

1. **编码器方向**：手动向前转左轮，打印 `Encoder_GetLeftCount()`。
   计数应**增加**。若减少，改 `stm32/encoder_tim.c` 顶部的
   `ENCODER_LEFT_DIRECTION_SIGN` 为 `-1`（右轮同理）。
2. **电机方向**：开环给左电机正 PWM（`Motor_SetLeft(+800)`），轮子应朝**前进**方向转。
   若反转，交换 `bsp_config.h` 里该侧的 IN1/IN2 定义。
3. **两者一致性**：给正 PWM 时计数必须增加。一正一负会直接触发
   `SPEED_CONTROL_FAULT_ENCODER_DIRECTION`。

> 不要用在上层加负号的方式"修正"方向。那会让后面每个读代码的人都困惑。

---

## 第 3 步：标定死区与前馈（架空，开环）

用 `CAR_MODE_BENCH_TEST` 模式，从 PWM = 0 每次 +50 递增，记录每个 PWM 对应的稳态速度。

**死区 `CAR_MOTOR_STARTUP_DEADZONE_PWM`**：
记下轮子**刚开始稳定转动**的 PWM 值，死区填**略小于**它的值（留给闭环向下修正的空间）。
本工程 MSPM0 平台实测起转约在 9.7% 占空比，对应 20kHz/3600 分辨率下约 350，
所以默认填 320。**换驱动、换电池、换车重都要重测。**

**前馈 `leftFeedforwardPwmPerCmps`**：
取中高速段两个点做线性拟合，斜率就是前馈系数：

```
前馈 = (PWM2 - PWM1) / (速度2 - 速度1)      单位 PWM/(cm/s)
```

前馈的作用是让 PID 只负责"修偏差"而不是"从零建立输出"，
加上前馈后 Ki 可以显著减小，超调也更小。前馈填 0 则完全关闭。

同时记录左右两侧差异。**同型号电机差 10%~20% 很正常**，所以本库左右参数独立。

---

## 第 4 步：调速度内环 PID（架空 → 落地）

内环目标：给定目标速度，实际速度快速跟上且不振荡。

顺序是 **P → I → D（D 通常不加）**：

1. **先只开 P**（`Ki = 0, Kd = 0`）。
   从 `Kp = 18` 开始，逐步加大到速度响应快但刚开始出现轻微振荡，然后退回 70%。
2. **再加 I**。从 `Ki = 轮Kp/3` 左右开始，目标是消除稳态误差（实际速度稳定到目标值）。
   - 若长时间到不了目标，**先怀疑 `integralLimit` 太小**，而不是 Ki 不够。
     积分限幅卡住时，表现和 Ki 不足一模一样。本库自测用例专门验证了这个现象。
3. **D 项默认保持 0**。10ms 一拍的编码器计数是整数，低速时速度量化步长约
   `1.42 cm/s`（见 `Encoder_SpeedQuantumCmps()`），D 项会把这个量化噪声放大成抖动。
   确实需要 D 时，先把 `feedbackFilterK` 降到 0.3~0.4 加强滤波。

**低速可分辨下限**：目标速度若低于约 2~3 个速度量化步长（本车约 3~4 cm/s），
反馈会严重跳变，闭环很难稳。此时应延长控制周期或接受开环。

---

## 第 5 步：标定光电探头

1. **确认编号方向**：遮住**最左**那颗探头，确认 `LineSensor_GetMask()` 的 **bit0** 置位。
   若实际是 bit7，说明接线顺序相反，调整 `app_chesscar.c` 里 `App_SampleLineSensor()`
   的位分配（**不要**去改 `line_follow.c` 的符号）。
2. **模拟量模块**：白底上调 `LineSensor_Calibrate(&s, adc, false)`，
   全压黑线上调 `LineSensor_Calibrate(&s, adc, true)`。
   归一化后白底应接近 0、黑线接近 1000。
3. **数字量模块**：转电位器，使探头在黑线正上方时 DO 翻转，且左右移动 2mm 内能稳定切换。
4. **离地高度**：默认 1cm。通道闪烁或黑白区分不稳时降到 0.6~0.8cm。
   反射式探头对高度非常敏感。

**偏差符号自检**：把车放在线左侧（线在车的右边），`LineSensor_GetError()` 应为**正**。

---

## 第 6 步：调循迹外环（落地，低速）

外环只用 **Kp 和 Kd**，`Ki` 保持 0（横向偏差加积分会让车在线上蠕动）。

1. 把 `baseSpeedCmps` 降到 8~10 cm/s 这类很慢的值起步。
2. 加 `kp` 直到车能跟线。**左右摇摆说明 kp 太大**，或外环周期太快。
3. 加 `kd` 压过弯超调。`kd` 过大会让车对探头噪声过度反应。
4. 稳定后再逐步提高 `baseSpeedCmps`，并用 `cornerSlowdownGain` 让大偏差时自动减速。

> **外环必须慢于内环。** 本库默认外环 20ms、内环 10ms。
> 若把外环也设成 10ms，内环还没跟上目标就被改目标，整车必然摇摆。

**微分项的坑**：外环 `previousError` 必须是**上一个控制周期**（20ms）的偏差。
如果探头采样是 10ms，绝不能用采样周期的 lastError 去覆盖它——
那样微分项的时间基准就错了，增益含义完全改变。本库已在 `line_follow.c` 中隔离。
